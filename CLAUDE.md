# Skill Stations Pack

Progression content for RPG Stations. The family-wide rules apply here; this file adds only what is specific to this pack. Authoring reference: RPG Stations `SCHEMA.md` and `docs/`.

- The Sawmill station and its presentation ship in the RPG Stations jar (its Mill action in the jar's `Actions/Mill.json`). This pack extends Mill through `RpgStations/Extensions/SawmillProgression.json` and must never re-ship a full `Stations/Sawmill.json`. A tree technique is a per-player setting on the station's ONE action (R764), never a variant action: the extension's per-worker overlays (`Recipe.Batch`, `Tool.Durability.Ladder`, `Pace`, `Work.Unattended`, a fallback route's `PreferWhen`, a beat's `SkipWhen` through `StepOverlays`) and gated rolls, so techniques combine and a pile stays everyone's.
- Every technique setting is opt-in, so a server with a tree switched off (or an unknown track) pays every default: a gate or roll condition asks `Min: 1` of the technique's own pick, and an everyday table a technique turns off carries a top-level `Requires` whose `Not` names that pick. Never gate a default path on `Max: 0` of a pick: `track_pick` reads null for an off or unknown track, which fails a `Max` closed and stops the default. Inside a roll already gated on a technique's `Min: 1`, a `Max` bound on a sibling pick of the same track is safe.
- The trees' station stats (the MMO's `MMO_Station*`, `MMO_StationYield_CRAFTING`, `MMO_StationPace_ENCHANTING`) are read only here, as a roll's `Chance` (whole percent points) in `Mmo_Sawmill_Talents`, `Mmo_Disenchant_Talents` and `Mmo_Disenchant_Queue_Talents`; a ladder reads a skill's main-line stat, never `MMO_Level_<SKILL>` (a level stays a gate's), and a technique reads `ziggfreedcommon:track_pick`. A find is rolled again by a `Lootable` reward naming its table, so keep one find per table. The tables' return talents share ONE slot read as a share of one more (each point a hundredth, held at 0.10, the rest of the room kept for tables to come), never a whole unit, since every output_items a ritual grants sums before one resolution: unmaking must always lose materials. Every other talent pays at a table in Essence of Life or a find (Crafting's main line included), never the recipe's material. A Greater (Concentrated) Essence of Life is worth 100 Essence of Life (vanilla's Farmingbench trades them both ways): size its chances at that rate.
- Same-id native item overrides (`RPG_Station_Sawmill.json`, `RPG_Tool_Hatchet_Sawmiller.json`) replace the jar item wholesale: carry every field of the jar's file and change only the delta (the block copy omits `Recipe` on purpose).
- `SawmillTrophy.json` overrides the jar's trophy table by id (the jar's Sawmill already references it); never also list it in `SawmillProgression`'s `Bonus.Lootables`.
- The Disenchanting Tables follow the Sawmill's split: the jar owns both stations, the `Disenchant` / `Disenchant_Greater` actions and their presentation. `DisenchantingProgression.json` extends the scoped lesser action, and `DisenchantingGreaterProgression.json` is its `Parent` child changing only `Target`, because extension additions never flow down the greater action's `Parent` chain. The jar's ritual is the short one (about 15 s, about 3 s at full proficiency); this pack makes it the long one from `DisenchantingProgression`'s `Pace` (`Stretch` 2.5, `Clamp.Min` 0.42 for the 15 s floor), and `DisenchantingProficiency.json` (with its greater `Parent` child) softens the jar's proficiency ladder back to the gentler curve: each floor is the wanted scale divided by the jar's, so a jar retune means recomputing them.
- Seven more same-id copies, under the same rule: the two table blocks (no `Recipe`, `Tags.Family` `MMOSkillTree`, so the questline is the only way to a table), the four `RPG_Armor_Disenchanter_*` pieces and `RPG_Weapon_Spellbook_Grimoire_Disenchanter` (each adds only its `MMO_StationYield_ENCHANTING` and `TrackGain_Enchanting` lines). No pack set file: the jar's `RPG_Disenchanters_Kit` keeps the tiers and the look.
- `Disenchant_Kit.json`, `DisenchantTrophy.json`, `Disenchant_Essence.json`, `Disenchant_Void.json` and `Disenchant_Greater_Bonus.json` override the jar's tables by id (the jar actions already list them); never list one in an extension's `Bonus.Lootables`. `Disenchant_Essence` carries the jar's wage ladder unchanged under a `Requires` for the trades that give it up (Rite of Purity, Void Rite); `Disenchant_Void` keeps only the jar's Void essence roll (its Voidheart roll moved to `Mmo_Disenchant_Voidheart_Base`) and `Disenchant_Greater_Bonus` only its essence roll (its Void roll moved to `Mmo_Disenchant_Greater_Void`), so Kit Rite can shut the Void finds; a jar retune of any of these means copying it again.
- `Disenchant_Kit` stays luck-only (no item, station or tool `Conditions`) because quest Claims name it; an item-gated table cannot pay from a Claim, so the pack's own claim tables are `Mmo_Enchanter_*`, beside the station tables `Mmo_Disenchant_*`.
- Orrin's Grimoire is kept off both tables by its own `RpgStations/ProtectLists/Mmo_Disenchanting_Tables_Earned.json`. Never name a protect-list file `Disenchanting_Tables.json`: a same-name file replaces the jar's whole list.
- A `DropLists` id repeated inside one `Grants` is deliberate: each entry rolls as an independent pull.
- Station bounties ship here, self-contained with no `Parent`, so each loads with nothing but this pack, RPG Stations and the MMO. This pack's hard dependency on RPG Stations keeps them off a server without stations, and their `mmoskilltree:feature` `Stations` condition (matched case-insensitively, so the shipped `stations` spelling still works), lifted out of the gate when a contract loads, keeps them out of a board's draw where stations are switched off.
- `unreleased/` (Anvil, Smithing and Cooking skills, `CookingProgression`) is excluded from the zip by `build.ps1` and is not live content; its README documents it and its lang keys stay shipped.
